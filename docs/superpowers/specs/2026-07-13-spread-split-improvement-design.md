# 見開き分割の改善 — 設計仕様書

作成日: 2026-07-13

> **改訂 (2026-07-13 実機検証後):** 分割判定の「綴じ目ストライプ検出 AND 人物数 >= 2」を
> **「黒マスク除去後が横長（アスペクト比 >= `MIN_SPREAD_ASPECT`=1.0）AND 人物数 >= 2」** に変更した。
> 実データで `detect_center_stripe` の検出率が 32 枚中 3 枚と低く、本物の見開き 27 枚が分割漏れした
> ため。単ページ／見開きは黒マスク除去後のアスペクト比（縦長 0.66 / 横長 1.33）で確実に判別できる。
> 問題2（中央 1 人の見切れ）は人数カウントの `count_persons` 切替（Task 4）だけで既に解決しており、
> 綴じ目条件は不要だった。綴じ目の検出・除去（ガター除去）自体は引き続き利用する。
> `action` の値は `"split" | "kept"` に整理（`"no_stripe"` は廃止）。

## 背景と課題

`backend/spread_splitter.py` の見開き分割機能に 2 つの不具合がある。

### 問題1: 両端の黒マスクが残る
元画像が `[黒マスク][左ページ][綴じ目][右ページ][黒マスク]` という構造のとき、
現状は中央の綴じ目ストライプのみ除去する。両端の黒マスクは一切処理されないため、
分割後の `_L` には左端の黒帯、`_R` には右端の黒帯が残る。

### 問題2: 中央 1 人の写真が見切れる
現状の分割判定は「人物数 ≥ 2」のみで、綴じ目ストライプの有無を条件にしていない。
さらに人数カウントに `count_persons_split`（画像を中央で割り左右 half を別々に検出）を
使っているため、**中央にまたがる 1 人の被写体を「左右両方に人物あり = 2」と誤判定**する。
結果、見開きでない単ページ写真が中央で分割され、被写体が真っ二つ・片側が見切れになる。

## 決定した要件

| 項目 | 内容 |
|------|------|
| 黒マスク範囲 | 左右の縦帯のみ（上下は対象外） |
| 分割条件 | 綴じ目ストライプ検出 **AND** 全体で 2 人以上（両方成立時のみ分割） |
| 黒マスク除去 | 常に前処理として適用（分割の有無に関係なく） |

## 新しい処理フロー（`process_spread` の再設計）

```
1. 画像を開く（EXIF 回転・RGB 変換）              … 既存
2. 左右の黒マスクを検出・トリミング              … 新規
3. 中央ストライプ検出 → あれば除去して結合         … 既存（トリミング後の画像に対して実行）
4. 全体画像で人物数カウント                      … 変更（中央またぎの 1 人を正しく 1 人と数える）
5. 分割判定 = ストライプ検出 AND 人数 ≥ 2          … 変更（AND 条件に）
   ├─ 成立   → 中央で左右分割 → images=[L, R], suffixes=["_L", "_R"]
   └─ 不成立 → トリミング済み画像 1 枚を保持 → images=[img], suffixes=[""]
```

## コンポーネント設計

### 新規: `detect_side_masks(image) -> tuple[int, int]`
左右端から中央に向かって列を走査し、黒マスク境界（content_left, content_right）を返す。

```
入力: PIL.Image（RGB）
1. 各列の平均輝度を計算（列ごとに全行の平均）
2. 「暗い列」の定義:
     列の平均輝度 < DARK_THRESHOLD
     かつ その列内の暗ピクセル率 > DARK_PIXEL_RATIO
   （暗ピクセル率も見ることで、下部に白い椅子・水面など明るい被写体があっても
     黒帯部分だけを正しく識別できる。純輝度平均だけだと被写体の影響を受けやすい）
3. 左端 x=0 から右へ、暗い列が連続する限り進む → content_left
4. 右端 x=W-1 から左へ、暗い列が連続する限り進む → content_right
5. 安全弁: content_left と (W - content_right) はそれぞれ画像幅の MAX_MASK_RATIO を上限にクランプ
6. 検出幅が MIN_MASK_WIDTH 未満の側はトリミングしない（誤トリミング防止）
7. 黒帯がなければ (0, W) を返す
```

戻り値は「残すコンテンツ領域」の x 範囲 `(content_left, content_right)`。

### 新規: `crop_side_masks(image, content_left, content_right) -> PIL.Image`
`image.crop((content_left, 0, content_right, height))` でトリミング画像を返す。
`(0, W)` の場合は元画像をそのまま返す（新規オブジェクト生成を避ける）。

### 変更: 人数カウント
- 分割判定から `count_persons_split`（左右 half 別々。中央またぎを誤カウント）を外す。
- トリミング後の全体画像に対する `count_persons`（YOLO の人物ボックス総数）に切り替える。
- 呼び出し側 `job_manager._process_spread_file` の `_count_fn` を
  `count_persons`（全体ボックス数）を使う形に変更する。

### 変更: `process_spread` の分割判定
```python
should_split = stripe_detected and person_count >= 2
```
（現状の `person_count >= 2` 単独から AND 条件へ）

## パラメータ（`spread_splitter.py` 冒頭に定数化）

| 定数 | 既定値 | 意味 |
|------|--------|------|
| `DARK_THRESHOLD` | 20 | 黒とみなす列平均輝度の上限（0–255） |
| `DARK_PIXEL_RATIO` | 0.95 | 列内で暗いピクセルが占める最低割合 |
| `MAX_MASK_RATIO` | 0.40 | 片側除去幅の上限（画像幅比。暴走防止） |
| `MIN_MASK_WIDTH` | 5 | これ未満の黒帯は無視 |

## エラー処理
- 黒マスク検出中の例外は握りつぶさずログ出力し、トリミングなし `(0, W)` にフォールバック
  （個別ファイルで全体を止めない既存方針を踏襲）。
- 画像全体が暗いケースは `MAX_MASK_RATIO` の安全弁で全消しを防ぐ。

## テスト方針（pytest — `tests/test_spread_splitter.py`）

1. **黒マスク検出**: 合成画像（左右に黒帯 + 中央にグレー矩形）で境界座標が正しいか
2. **黒帯なし**: 通常画像で `(0, W)` が返る（トリミングされない）
3. **安全弁**: ほぼ真っ黒な画像で `MAX_MASK_RATIO` 上限が効く
4. **明るい被写体との共存**: 黒帯の反対側に明るい矩形を置いても黒帯だけ検出される
5. **分割条件の AND**（`count_persons` をモック）:
   - ストライプあり × 2 人 → 分割
   - ストライプあり × 1 人 → 非分割
   - ストライプなし × 2 人 → 非分割
6. **統合**:
   - 問題1相当（黒帯 + 綴じ目 + 2 人）→ `_L`/`_R` に黒帯が残らない
   - 問題2相当（黒帯 + 中央 1 人）→ 分割されずトリミングのみ
